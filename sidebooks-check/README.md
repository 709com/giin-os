# SideBooks 新着チェック（先生のPC用）

文京区議会の資料棚「SideBooks Cloud」（https://bunkyo-gikai.backshelf.jp/）に先生のアカウントでログインし、棚全体の一覧を前回と比べて、**新しく増えたファイル**を知らせる道具です。

- 動かす場所：**先生のWindows PC**（「議員所有情報通信端末の会議システム使用届」を提出済みの端末）
- 見るだけです。アップロード・削除・移動・名前変更はしません。万一押し間違えても、変更につながる通信は止める安全装置を入れています。
- 画面に出ている一覧を読み取ります。画面の裏の仕組みを解析して直接呼ぶ方法は使っていません（運営会社の規約 第31条に配慮）。
- 1画面ごとに1.5秒あけて、1日1回だけ動かします。
- 先方の負担を減らすため、見る範囲を日によって変えます（2026年11月11日 先生の指定）。

  | いつ | 見るフォルダ |
  |---|---|
  | 毎朝 | 「令和○年○月定例議会」（新着が入る最重要の場所）、「03 その他会議」（中の「※開催終了分」「old」「議員研修会」「議連名簿」と、「今後の議会運営に係る懇談会」の過去の年度は除く）、「04 幹事長会 / 今年度」 |
  | 日曜 | 毎朝の分＋「09 各種様式・便利情報・参考資料 / 調査結果 / 今年（R○）」と「… / 各種計画等」 |
  | 第1日曜 | 棚全体 |

  「今年度」「R○」は今の年度・年（2026年11月なら令和8年度・R8）。4・5月は前年度のフォルダも毎朝見ます。いますぐ棚全体を見たいときは `manual.bat --full`。
- これに加えて、**毎回 SideBooks の「新着ファイル」画面（https://bunkyo-gikai.backshelf.jp/?new）も見ます**。ここには先生が見られる資料のうち直近10日分が並ぶので、上の表で見ないフォルダ（「02 委員会」など）に入った新着もここで拾えます。記録にない資料だけ、詳細（ⓘ）を開いて置き場所を調べます。
- フォルダには入ったのに「新着ファイル」画面に出なかった資料があれば、知らせの最後に「（新着ファイル画面には出ていなかったもの）」として書きます（閲覧者を限定した資料が新着画面に出るかを確かめるため）。
- 資料が「開催終了分」など別のフォルダへ移されただけのときは、新着として知らせません（資料の番号で見分けます）。

## 結果の出方

| 場合 | 画面・log.txt | LINE |
|---|---|---|
| 新着あり | 「フォルダパス / ファイル名」の一覧 | 同じ一覧と保存先 |
| 新着なし | 「新着なし」の1行 | 送らない |
| 初回 | 記録（snapshot.json）を作り、フォルダ構成を要約 | 送らない |

- 2回目からは、**新着ファイルだけ**をGoogleドライブの「SideBooks新着\日付」フォルダに保存します。保存は Google Drive for desktop の「マイドライブ」を自動で探して行います。
- 同じ名前で更新日だけ変わったファイルは「（更新）」と書いて知らせます。ダウンロードはしません。
- 資料名の一覧（snapshot.json）、ダウンロードしたファイル、記録（log.txt）は、**PCの中だけ**に置きます。GitHubには上がりません。

## はじめの準備（1回だけ）

PCのClaude Codeに「sidebooks-check の準備と動作確認をして」と頼めば、2・3以外はやってくれます。

1. **プログラムを入れる**
   コマンドプロンプトで、giin-os を置きたい場所（例：`D:\AI作業用`）に移動してから、次を実行します。
   ```
   git clone -b claude/beautiful-euler-5pmcfi https://github.com/709com/giin-os.git
   cd giin-os\sidebooks-check
   npm install
   npx playwright install chromium
   ```
   （Node.js がなければ https://nodejs.org/ から「LTS」版を入れます）

2. **SideBooks のIDとパスワードを登録する**（画面や記録には出ません）
   Windowsのスタート →「環境変数」と入力 →「環境変数を編集」→ 上の段（ユーザー環境変数）の「新規」で2つ足します。
   - 変数名 `SIDEBOOKS_USER`、値：SideBooks のユーザー名
   - 変数名 `SIDEBOOKS_PASS`、値：SideBooks のパスワード

   登録しない場合は、手で動かしたときに入力を求められます。ただし、毎朝の自動実行は登録しないと動きません。

3. **LINEで受け取るための鍵を登録する**（2と同じ画面）
   - `LINE_CHANNEL_TOKEN`：GitHub に登録してあるものと同じ値。LINE Developers の「Messaging API設定」→「チャネルアクセストークン」で確認できます。
   - `LINE_USER_ID`：同じく GitHub と同じ値。LINE Developers の「チャネル基本設定」→「あなたのユーザーID」で確認できます。

   登録したら、コマンドプロンプトを開き直してください。

4. **1フォルダだけで試す**（記録もLINE送信もしません）
   `manual.bat --test` をコマンドプロンプトで実行します。R8.11.9 のフォルダの中身が一覧で出れば成功です。
   うまく出ないときは `manual.bat --test --debug` を実行します。すると、画面の作りが `debug\` に保存されるので、PCのClaude Codeに見せて直してもらってください。

5. **初回（記録づくり）**
   `manual.bat --no-download` を実行します。棚全体をたどるので、フォルダの数によっては数十分かかります。

6. **毎朝の自動実行を登録する**
   `register-task.bat` をダブルクリックします。毎朝7:10に実行し、結果は `log.txt` にたまります。
   - PCの電源が切れている時やスリープ中は動きません。
   - 第1日曜の朝は棚全体をたどるので、終わるまで1時間ほどかかります（ふだんの朝は10分ほど）。
   - 時刻を変えたいときは、Windowsの「タスク スケジューラ」で「SideBooksCheck」を開いて変えます。

## ふだんの使い方

- 自動：何もしなくてよいです。新着があればLINEに届きます。
- 手で今すぐ確認：`manual.bat`（ダブルクリックでも可）

## 細かい設定（環境変数・なくても動く）

| 名前 | 意味 | 決まっていない時 |
|---|---|---|
| `SIDEBOOKS_SAVE_DIR` | 新着の保存先フォルダ | マイドライブ\SideBooks新着（なければ sidebooks-check\downloads） |
| `SIDEBOOKS_WAIT_MS` | 1画面ごとの間隔（ミリ秒） | 1500 |

## 困ったとき

- 「ログインできませんでした」：2で登録したユーザー名・パスワードを確かめてください。
- 「画面の件数表示と読み取った数が違います」：画面の作りが想定と違います。4の `--debug` で調べます。
- 「ダウンロードボタンが見つかりません」：その資料のダウンロードが許可されていない可能性があります。一覧への記録と知らせは届きます。
